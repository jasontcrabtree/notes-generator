## Short Version

`SwiftData` is for persistence. `@Observable` is for UI state propagation.

If the object needs to survive app launches, participate in queries, or be stored
in a model context, make it a SwiftData model. If the object describes temporary
screen state, coordination state, or a service-like object that SwiftUI should
react to, make it observable.

## Mental Model

Use `@Model` when the object is part of your app's data graph.

Use `@Observable` when the object is part of your app's runtime behavior.

The overlap is that both can cause SwiftUI views to update, but they are solving
different problems. Treating SwiftData as a general state-management system tends
to make transient UI behavior harder to reason about.

## Code Example

```swift
@Observable
final class EditorState {
    var selectedID: UUID?
    var isInspectorVisible = false
}

@Model
final class Note {
    var title: String
    var body: String

    init(title: String, body: String) {
        self.title = title
        self.body = body
    }
}
```
